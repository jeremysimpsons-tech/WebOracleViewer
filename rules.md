# Project rules

always build secure and robust solutions based on latest technology trends and always ask me a few questions before building so you understand what i want you to do.

## How to apply this

- Ask a few concrete questions before adding a feature or changing behavior, unless the request already answers them.
- Prefer a current, supported stack and a small service that can be installed on Red Hat over a one-off script.
- Keep the admin session separate from database passwords. Encrypt secrets at rest. Fail with the Oracle error and the next useful grant when a view is missing.
- Do not weaken sign-in, CSRF protection, wallet path checks, or read-only mode to make a demo shorter.
- Update `README.md`, `documentation.md`, and `architecture.md` when an operator-visible behavior, label, port, or script name changes.
